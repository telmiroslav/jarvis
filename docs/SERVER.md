# Сервер Jarvis («мозг» на ноутбуке)

Программа на Python, которая слушает плату по Wi-Fi (протокол: [PROTOCOL.md](PROTOCOL.md)), распознаёт речь,
спрашивает Gemini, озвучивает ответ клонированным голосом и отдаёт звук обратно на плату. Всё тяжёлое (распознавание
речи и голос) работает на видеокарте ноутбука, к Google ходит только текст. Версия сервера 0.2.0 (приходит на плату в
`welcome.server`, пишется первой строкой лога, `python -m jarvis_server --version`): добавлен режим «слово Джарвис»
(прошивка платы v0.4.0), см. раздел «Режимы разговора».

```
плата --речь 16 кГц--> [Whisper large-v3-turbo] --текст--> [Gemini, потоком] --предложения--> [OmniVoice, клон голоса]
плата <--звук 24 кГц-- (подача по часам, не больше 1,5 с вперёд) <-------------------------------------+
```

## Установка (Давид)

Нужно: Arch Linux, видеокарта NVIDIA с драйвером, около 15 ГБ свободного места, включённый VPN (модели качаются с
huggingface.co, ИИ работает через Google), ключ Gemini и файл `jarvis_voice.zip` от Мирослава (образец голоса).

```
git clone https://github.com/telmiroslav/jarvis.git && cd jarvis && ./server/install.sh
```

(если репозиторий уже есть: `cd jarvis && git pull && ./server/install.sh`; повторный запуск безопасен и служит обновлением.)

Что делает установщик (по-русски объясняет каждый шаг, лог сохраняет в `~/jarvis-logs/server-install-*.log`):

1. Проверяет Arch, `nvidia-smi` (если драйвера нет, пишет, что поставить: `sudo pacman -S nvidia-open nvidia-utils`, и
   перезагрузку), версию драйвера (нужен 570+ для CUDA 12.8) и место на диске.
2. Спрашивает ключ Gemini (ввод скрытый; можно пропустить и позже выполнить `./server/set_key.sh`).
3. Спрашивает путь к `jarvis_voice.zip` (по умолчанию самый свежий `~/Downloads/jarvis_voice*.zip`), распаковывает
   в `~/.config/jarvis/voice/` (`ref.wav` или `ref.mp3` и `ref.txt`).
4. Один раз просит пароль sudo: `pacman -S --needed uv git` (если их нет) и правила UFW только для домашней сети
   `192.168.0.0/16`: UDP 47800 и TCP 47801 (если UFW включён; из интернета и из VPN порты остаются закрытыми).
5. Создаёт окружение `~/.local/share/jarvis/venv` (Python 3.12 от uv, PyTorch 2.8.0 для CUDA 12.8, остальное по
   `server/requirements.lock`, версии зафиксированы).
6. Заранее скачивает модели (распознавание около 1,6 ГБ, голос около 2,5 ГБ).
7. Ставит пользовательскую службу `jarvis-server.service` (`Restart=on-failure`).
8. Самопроверка: грузит модели, синтезирует фразу, распознаёт её обратно, печатает время и занятую видеопамять,
   одним крошечным запросом проверяет Gemini. Если всё хорошо, включает автозапуск и запускает службу.
9. Печатает итог: адрес ноутбука, как смотреть лог, как собрать отчёт.

Служба стартует при входе в систему. Чтобы сервер поднимался при загрузке ещё до входа, выполни один раз
`sudo loginctl enable-linger $USER` (обычно не нужно, установщик только напомнит).

## Каждый день

| Что | Команда |
|---|---|
| Живой лог (после каждой фразы строка `TURN` со временем) | `journalctl --user -u jarvis-server -f` |
| Работает ли | `systemctl --user status jarvis-server` |
| Перезапустить (после правки настроек) | `systemctl --user restart jarvis-server` |
| Задать/сменить ключ Gemini | `./server/set_key.sh` |
| Отчёт для Мирослава (лог, тайминги, nvidia-smi; ключ скрыт) | `./server/report.sh` (файл в `~/jarvis-logs/server-<дата>.txt`) |
| Запуск в терминале для отладки | `./server/run.sh` (службу на это время останавливает) |
| Обновить | `cd jarvis && git pull && ./server/install.sh` |

Загрузка моделей при старте занимает 30-60 секунд. Плата ищет сервер сама (UDP broadcast), если не нашла, адрес можно
задать в консоли платы: `server ws://<адрес ноутбука>:47801/ws`.

## Настройки

Файл `~/.config/jarvis/server.env` (права 600), строки `ИМЯ=значение`. Для разработки дополнительно читается
`<репозиторий>/.env` (в git не попадает). Приоритет: переменные окружения, `server.env`, `.env`. После правки:
`systemctl --user restart jarvis-server`.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `GEMINI_API_KEY` | нет | ключ Gemini (в логи и отчёты не попадает) |
| `JARVIS_LLM_MODEL` | `gemini-3.5-flash-lite` | модель Gemini |
| `JARVIS_LLM_FALLBACK` | `gemini-3.1-flash-lite` | запасные модели через запятую (при 429/5xx/404 до начала ответа) |
| `JARVIS_LLM_BACKEND` | `auto` | `gemini` (ключи AI Studio, в том числе вида `AQ.`...), `vertex` (Vertex express), `auto` (сначала gemini, при ошибке доступа vertex) |
| `JARVIS_LLM_THINKING` | `auto` | размышления модели: `auto` (самый короткий режим, который принимает модель), `off`, `minimal`, `low`, `medium`, `high` |
| `JARVIS_LLM` | `gemini` | `mock` = заготовленные ответы без интернета (проверка конвейера) |
| `JARVIS_STT_MODEL` | `large-v3-turbo` | модель Whisper (`small`, `medium`, `large-v3` ...) |
| `JARVIS_STT_DEVICE` | как `JARVIS_DEVICE` | `cuda` / `cpu` |
| `JARVIS_STT_COMPUTE` | `auto` | `auto`: на картах до 9 ГБ `int8_float16`, иначе `float16`; на процессоре `int8` |
| `JARVIS_STT_HOTWORDS` | `Джарвис` | подсказка Whisper (`hotwords` faster-whisper): слова, написание которых он предпочитает, чтобы имя выходило «Джарвис», а не «Жарбис» или «Джервис». Несколько слов через запятую; пустое значение (`JARVIS_STT_HOTWORDS=`) выключает. Измерения ниже |
| `JARVIS_STT_PROMPT` | пусто | `initial_prompt` Whisper (пример фразы). Включать не советую: в шуме Whisper повторяет эту фразу как будто её сказали (см. измерения ниже) |
| `JARVIS_TTS_STEPS` | `32` | шагов диффузии голоса: больше = качественнее и медленнее (8 и 16 заметно быстрее) |
| `JARVIS_TTS_DTYPE` | `auto` | `fp16` / `bf16` / `fp32`. `auto`: микротест видеокарты при старте; fp16, если он быстрее fp32 (RTX с тензорными ядрами), иначе fp32 (GTX 16xx) |
| `JARVIS_DEVICE` | `auto` | `cuda` / `cpu` для всего сразу |
| `JARVIS_TTS_REF_MAX_S` | `6.5` | сколько секунд образца голоса брать (режется по паузе между предложениями) |
| `JARVIS_FIRST_CHUNK_MAX_CHARS` | `80` | первое предложение длиннее режется по запятой, чтобы первый звук был раньше (0 = не резать) |
| `JARVIS_MEMORY_TURNS`, `JARVIS_MEMORY_IDLE_S` | `10`, `600` | память разговора: последние обмены; сброс после 10 минут тишины |
| `JARVIS_PACING_BURST_S`, `JARVIS_PACING_MAX_LEAD_S`, `JARVIS_SUBTITLE_LEAD_S` | `0.5`, `1.5`, `0.4` | подача звука (см. ниже) |
| `JARVIS_ALLOW_NETS` | пусто | сузить допустимые сети, например `192.168.1.0/24` (по умолчанию любые частные адреса) |
| `JARVIS_LOG_LEVEL`, `JARVIS_SAVE_UTTERANCES` | `INFO`, `0` | подробность лога; `1` = сохранять последнюю запись микрофона в `~/.local/share/jarvis/last_utterance.wav` |

Что скачивается при смене `JARVIS_STT_MODEL`: запусти `./server/install.sh`, он докачает (сервер работает с моделями
из кеша, без обращения к интернету при старте).

## Строка с таймингами

После каждого хода в лог пишется одна строка, например:

```
TURN ok stt_ms=312 llm_first_token_ms=980 first_sentence_ms=1450 tts_first_audio_ms=620 total_to_first_audio_ms=2490 total_turn_ms=8320 audio_s=7.4 | sentences=3 tts_ms=1800 tts_rtf=0.24 underruns=0 max_gap_s=0.00 chars=210 model=gemini-3.5-flash-lite tools=get_time mode=wake
```

| Поле | Что мерится |
|---|---|
| `stt_ms` | распознавание речи |
| `llm_first_token_ms` | от запроса к ИИ до первого слова ответа |
| `first_sentence_ms` | от запроса к ИИ до готового первого предложения (его уже можно озвучивать) |
| `tts_first_audio_ms` | синтез первого предложения |
| `total_to_first_audio_ms` | от `listen_stop` (кнопку отпустили) до первого кадра звука, ушедшего на плату: то, что чувствует человек |
| `total_turn_ms` | от `listen_stop` до `audio_end` (звук отдаётся по часам, поэтому включает почти всё время речи) |
| `audio_s` | сколько секунд звука отправлено |
| `tts_rtf` | время синтеза / длительность звука (меньше 1 = синтез быстрее речи, предложения успевают) |
| `underruns`, `max_gap_s` | сколько раз и как надолго речь прерывалась, потому что следующее предложение не успели синтезировать |

| `mode` | как началась запись: `ptt` (кнопка BOOT) или `wake` (слово «Джарвис»); всегда последний ключ строки |

Итог `outcome`: `ok`, `aborted`, `error`, `empty(...)` (причина в скобках: `short`, `silence`, `no_speech`, `junk` для
выдуманных Whisper фраз, `wake_only` когда сказано только «Джарвис»), `disconnected`. Строки `TURN` собирает `report.sh`
вместе с медианой и разбросом; новый ключ `mode` ему не мешает.

## Режимы разговора: кнопка (ptt) и слово «Джарвис» (wake)

Плата v0.4.0 сама ловит слово «Джарвис» (на сервер звук до этого не идёт), после чего шлёт `listen_start` с
`"mode":"wake"`, звук с момента сразу после слова и `listen_stop`, когда услышала 0,8 с тишины (или 5 с без речи, или
прошло 12 с). Для сервера это тот же ход, что и по кнопке: тот же конвейер, те же тайминги. Отличия только такие:

- `mode` попадает в лог (`Вы (wake): ...`) и последним ключом в строку `TURN` (`mode=wake`). Без поля (старые прошивки)
  считается `ptt`. Неизвестное значение не отвергается: сервер пишет в лог предупреждение и ведёт себя как в `ptt`.
- Из распознанного текста снимается обращение в начале фразы, и в ИИ, в субтитр `user_text` и в память разговора
  идёт уже текст без него: «Джарис, ты меня слышишь?» превращается в «Ты меня слышишь?». Исходная фраза остаётся в логе
  строкой `обращение снято`.
- Если после снятия ничего не осталось (человек сказал только «Джарвис» или «Привет, Джарвис», или в запись попал один хвост
  слова), ход заканчивается так же, как при пустой речи: `state idle`, без `user_text`, ответа и обращения к ИИ
  (`TURN empty(wake_only)`).

Что снимается (функция `strip_wake_word` в `textnorm.py`, чистая, с тестами):

| Режим | Снимается в самом начале фразы | Не снимается |
|---|---|---|
| `wake` | имя во всех написаниях Whisper (джарвис, жарвис, джарис, джервис, джарвиз, джарви, дарвис, ярвис, `jarvis`...) с «привет / здравствуй / эй / слушай / ну» перед ним и запятой, тире, двоеточием после; повторы («привет жарвис привет жарвис»); одинокий хвост слова пробуждения «вис», «рвис» | имя внутри фразы («расскажи про Джарвиса»), слова вроде «дарвинизм», «через», «сервис», «вес»; «привет» без имени |
| `ptt` и неизвестные | только имя в самом начале и только если дальше есть слова: «Джарвис, включи свет» -> «Включи свет» | «привет, Джарвис, ...» (оставляется как сказано), текст из одного «Джарвис» (пустым не становится) |

Для обоих режимов: слово-«клик» от кнопки перед обращением («кнопки привет джарвис ...») тоже снимается. После снятия
первая буква делается заглавной (для субтитра).

### Подсказка для имени (hotwords): что измерено

Без подсказки Whisper пишет имя по-разному: «Джарис», «Жарвис», «Джервис», «Жарбез», «Jarvis». Снятие обращения (выше)
эти варианты переживает, но в субтитре и в запросе к ИИ имя лучше видеть правильным. Проверка на видеокарте разработчика
(GTX 1650, `int8`): 16 фраз, озвученных голосом проекта, каждая чисто, с шумом микрофона 15 дБ и 5 дБ (48 клипов); ещё 48
контрольных клипов со словами, похожими на имя; 62 клипа шума и тишины (белый и розовый шум -60...-25 дБ, гул, щелчки,
нули; 2 и 5 секунд), из них 31 ещё и без VAD. Живой речи с платы в выборке нет, поэтому цифры дают ориентир, а не гарантию.

| Вариант | Сказано «Джарвис» (24 клипа): записано «Джарвис» / иначе / имя пропало | Сказано «Жарвис», «Ярвис», «Дарвис» (9): записано «Джарвис» | Слова фразы после снятия имени (48) | Мусор на шуме: с VAD (как на сервере) / без VAD | Время |
|---|---|---|---|---|---|
| без подсказки (было) | 17 / 7 / 0 | 0 | 48 верно | 0 из 62 / 31 из 31, весь отфильтрован | 1838 мс |
| `hotwords=Джарвис` (**по умолчанию**) | 21 / 0 / 3 | 2 | 48 верно | 0 из 62 / 31 из 31, весь отфильтрован | 1840 мс |
| `initial_prompt` с примерами фраз | 20 / 0 / 4 | 8 | 48 верно | 0 из 62 / 31 из 31, 1 повтор подсказки прошёл фильтр | 1853 мс |
| оба вместе | 20 / 0 / 4 | 8 | 46 верно («Дарвина» -> «Дарвиной») | 0 из 62 / 31 из 31, 4 повтора подсказки прошли фильтр | 1848 мс |

- Взято `hotwords`: из 7 ошибочных написаний («Жарбез», «Джарис», «Джервис» дважды, «Жаргиз», «Жарбис», «Jarvis») исправлено 5;
  в одном клипе имя пропало, в одном (шум 5 дБ, одно слово «Джарвис») вместо слова пришла фраза-мусор «Субтитры подогнал ...»,
  фильтр её отбрасывает. Слова фразы не пострадали; в клипах без имени «Джарвис» не появляется ни разу (15 клипов во всех
  вариантах и 36 в сравнении только с прежним поведением); имя в середине фразы не теряется («кота Джарвис», «создал
  Джарвиса»); на похожих словах (Дарвин, Гарвард, Харви, дервиш, сервис, жарко, ярлык) результат тот же, что без подсказки,
  в 43 клипах из 48, из остальных 5 три лучше («Харли» -> «Харви», «Напомню» -> «Напомни», «включить» -> «Включи»), один хуже
  («Закажи» -> «Закажет»), один нейтрально; время не меняется. Выигрыш скромный: слова фразы без подсказки тоже верны.
- `initial_prompt` не взят: лучше всех нормализует имя, но в шуме без VAD выдаёт саму подсказку («Джарвис, включи свет.»), и
  это уже не отфильтровать как мусор: ИИ получил бы выдуманную команду. На сервере VAD включён и такого не случилось ни
  разу, но ложное срабатывание VAD на шуме комнаты возможно. Подсказка с примерами ещё и коверкала обычное слово
  («одетым» -> «о детом»).
- Мусор Whisper на шуме без VAD («Продолжение следует...», «Субтитры создавал DimaTorzok», «Субтитры подогнал ...»)
  фильтр `stt.py` отбрасывает (в логе `STT: отброшен мусор Whisper`, `TURN empty(junk)`). Фильтр дополнен пометками звука
  целиком («[Музыка]», «(аплодисменты)») и прощаниями целиком («Спасибо за внимание»); сами по себе «спасибо», «пока»
  остаются речью.
- С подсказкой Whisper иногда вовсе не пишет имя («Включи музыку.»): серверу это не мешает, имя всё равно снимается.

Чтобы вернуть прежнее поведение: `JARVIS_STT_HOTWORDS=` (пусто) в `~/.config/jarvis/server.env` и перезапуск.

## Как реализован протокол

- Поиск: UDP-ответчик на порту 47800, в ответе IP того интерфейса, на который пришёл запрос (`IP_PKTINFO`).
  Отвечает только отправителям из частных сетей.
- WebSocket `/ws` на 47801, один разговор за раз: новое подключение вытесняет старое. Подключения не из локальной сети
  получают 403. Свои пинги на уровне WebSocket (каждые 20 с) плюс прикладные `ping`/`pong`: `pong` уходит сразу, даже
  когда идёт генерация ответа.
- Ход: `state thinking` → `user_text` → `state speaking` → `jarvis_text` + `audio_start` + кадры по 40 мс → … →
  `audio_end` → `state idle`. `audio_start.rate` всегда 24000. Каждое `jarvis_text` не длиннее 450 символов.
- Субтитр: `jarvis_text` предложения N+1 уходит, когда в буфере платы остаётся не больше `JARVIS_SUBTITLE_LEAD_S` (0,4 с)
  звука предыдущего предложения, то есть почти в момент, когда зазвучит его звук. Последнее предложение идёт с `final:true`;
  если ИИ закончил без нового предложения (например, замолчал после вызова функции), сервер добавляет пустое
  `{"type":"jarvis_text","text":"","final":true}`.
- Подача звука: первые 0,5 с сразу, затем быстрее реального времени вдвое, пока опережение не дойдёт до 1,5 с, дальше
  по часам. Пока плата проигрывает предложение, следующее уже синтезируется. Если оно не успело, плата проигрывает
  тишину (в лог: «пауза в речи»).
- `abort`: отмена всего (ИИ, очередь озвучки, отправка), ответ `audio_end` (если звук шёл) и всегда `state idle`.
  Новый `listen_start` во время ответа тоже отменяет ответ, но молча: плата сама знает, что слушает.
- Обрыв связи с платой посреди хода отменяет ход.
- Ошибки: `state error` с короткой русской подсказкой (нет связи с ИИ/VPN, ключ, лимит запросов, перегрузка, сбой
  голоса). После `error` сервер `idle` не шлёт: плата сама решает, когда вернуть лицо.
- Запись короче 0,3 с речи (плюс ~0,2 с «до-записи», которую плата добавляет в начало) сразу даёт `state idle` без ответа.
  Тишина и мусор распознавания тоже кончаются на `idle`.

## Как добавить умение (управление ПК, музыка, свет)

Функции, которые ИИ может вызывать, лежат в `server/jarvis_server/skills/`. Новое умение это обычная функция:

```python
# server/jarvis_server/skills/builtin.py
@registry.tool(description="Включить музыку. Вызывай, когда просят музыку.")
def play_music(query: str, volume: int = 30) -> dict:
    ...
    return {"ok": True, "playing": query}
```

Параметры берутся из аннотаций типов (`str`, `int`, `float`, `bool`; без значения по умолчанию = обязательный),
описание из `description` или docstring. Функция может быть `async`. Исключение превращается в `{"error": ...}`, и ИИ
объяснит ошибку человеку. Реестр передаётся Gemini как набор функций, цикл вызова ручной: перед вызовом функции текст,
который ИИ уже сказал («Сейчас посмотрю»), озвучивается, пока функция выполняется. Сейчас есть одна функция,
`get_time` (время и дата в часовом поясе ноутбука; можно спросить и другой пояс).

## Разработка и проверка

Всё из `server/`, окружение то же (`~/.local/share/jarvis/venv`) или своё по `requirements-dev.txt`.

- Тесты: `pytest` (около 270: протокол, снятие обращения «Джарвис», распознавание на подделке модели, машина состояний, деление на предложения, числа и даты, подача звука, поиск по
  UDP, WebSocket на живых сокетах, цикл вызова функций Gemini на подделке SDK, скрипты установки). Моделей и интернета не нужно.
- Сквозная проверка без платы: `server/tools/fake_board.py вопрос.wav` притворяется платой (поиск по UDP или `--url`),
  отправляет WAV как 16 кГц по 40 мс, пишет хронологию сообщений, сохраняет звук ответа в WAV (звук не проигрывается),
  проверяет протокол и опережение звука. `--abort-after-audio 2` нажимает «abort» через 2 с после первого звука;
  несколько WAV подряд = несколько ходов на одном подключении (проверка памяти). `--mode wake` шлёт `listen_start` с
  `"mode":"wake"`, как плата v0.4.0 (по умолчанию `ptt`).
- Без ключа и без видеокарты: `JARVIS_LLM=mock JARVIS_TTS=mock JARVIS_STT_MODEL=mock ./server/run.sh`.
- Образец голоса для Давида: `server/tools/make_voice_zip.sh ref.wav ref.txt jarvis_voice.zip`. В образце нужен
  дословный текст, числа словами, лучше 8-12 секунд ровной речи без шума. Образец личный: в репозиторий не кладём.
- `python -m jarvis_server config` показывает итоговые настройки (без ключа), `python -m jarvis_server check-llm` проверяет Gemini.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| Установщик: «Видеокарта NVIDIA не отвечает» | поставить драйвер (команда в тексте установщика), перезагрузиться |
| В `journalctl`: `out of memory` | видеокарту занимает ещё что-то (`nvidia-smi`) или памяти мало: `JARVIS_STT_DEVICE=cpu` в `server.env` |
| Лицо платы: «Не могу связаться с ИИ. Проверь VPN» | VPN выключен, или Google недоступен из этой сети; `./server/set_key.sh` покажет, отвечает ли Gemini |
| «ИИ не принял ключ» | ключ неверный или без доступа: `./server/set_key.sh` |
| Плата не находит сервер | `systemctl --user status jarvis-server`; `sudo ufw status` (должны быть UDP 47800 и TCP 47801 от 192.168.0.0/16); адрес вручную в консоли платы |
| Речь после пробуждения ноутбука не работает | сбой видеокарты после сна: сервер сам перезапускается (`Restart=on-failure`), занимает около минуты |
| Плата слушает после слова «Джарвис», но не отвечает | в логе `TURN empty(wake_only)`: распознано только имя (сказано «Джарвис» и пауза); `empty(no_speech)` или `empty(silence)`: плата услышала тишину; `empty(junk)`: Whisper выдумал фразу из шума, отброшена |
| Не уверен, что происходит | `./server/report.sh` и прислать файл Мирославу |
