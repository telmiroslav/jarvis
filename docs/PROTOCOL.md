# Протокол плата ↔ сервер (версия 1)

Плата (ESP32-S3) и сервер (ноутбук Давида) в одной домашней сети. Домашняя сеть 192.168.0.0/16
исключена из VPN-туннеля ноутбука, поэтому плата ходит к серверу напрямую. Шифрования нет (только LAN).

## 1. Поиск сервера

- Плата шлёт UDP broadcast на `255.255.255.255:47800` строку `JARVIS_DISCOVER 1` раз в 3 с,
  пока не найдёт сервер (и после каждой потери связи).
- Сервер отвечает на адрес отправителя строкой `JARVIS_SERVER 1 ws://<ip>:47801/ws`.
- Плата запоминает адрес в NVS. Команда в консоли `server ws://<ip>:47801/ws` задаёт его вручную,
  `server auto` возвращает поиск.

## 2. WebSocket

`ws://<ip>:47801/ws`. Текстовые кадры: JSON (UTF-8). Бинарные кадры: звук PCM16 little-endian, моно.

### Плата → сервер

| Сообщение | Когда |
|---|---|
| `{"type":"hello","proto":1,"fw":"v0.4.0","mac":"10:51:db:..","mic_rate":16000,"spk_rate":24000}` | сразу после подключения |
| `{"type":"listen_start","mode":"ptt"}` | зажата BOOT |
| `{"type":"listen_start","mode":"wake"}` | плата сама услышала слово «Джарвис» (раздел 7); и когда слово перебило ответ (раздел 9) |
| `{"type":"listen_start","mode":"follow"}` | плата услышала голос без слова в окне после ответа (раздел 8, v0.4.2) |
| бинарные кадры, 16 кГц, 20–100 мс каждый | только между `listen_start` и `listen_stop` |
| `{"type":"listen_stop"}` | BOOT отпущена; или плата сама решила, что фраза кончилась (раздел 7); или BOOT нажата посреди записи по слову |
| `{"type":"abort"}` | короткое нажатие BOOT, пока Джарвис думает или говорит: замолчать; и слово «Джарвис» посреди ответа (v0.4.2): `abort`, сразу за ним `listen_start` (раздел 9) |
| `{"type":"ping"}` | раз в 10 с без другого трафика |

### Сервер → плата

| Сообщение | Смысл |
|---|---|
| `{"type":"welcome","proto":1,"server":"0.2.0","tts_rate":24000}` | ответ на `hello` |
| `{"type":"state","state":"thinking"\|"speaking"\|"idle"\|"error","msg":"..."}` | что показать на лице; `msg` (по-русски) только для `error` |
| `{"type":"user_text","text":"..."}` | что распознано из речи пользователя (субтитр «Вы: …») |
| `{"type":"jarvis_text","text":"...","final":false}` | очередное предложение ответа; плата ДОПИСЫВАЕТ его к субтитру; `final:true` у последнего |
| `{"type":"audio_start","rate":24000}` | дальше идут бинарные кадры ответа |
| бинарные кадры, 24 кГц | голос Джарвиса |
| `{"type":"audio_end"}` | ответ закончился, плата доигрывает буфер и уходит в `idle` |
| `{"type":"pong"}` | ответ на `ping` |

## 3. Обычный разговор

```
плата: listen_start → [звук 16 кГц ...] → listen_stop
сервер: state thinking → user_text → jarvis_text(1) → audio_start → [звук 24 кГц] →
        jarvis_text(2) → [звук] → ... → jarvis_text(final) → audio_end → state idle
```

- Лицо: LISTENING, пока идёт запись (плата сама: кнопка зажата или идёт запись по слову); THINKING и SPEAKING по `state` от сервера.
- Субтитр предложения показывается, когда начинает звучать его звук (сервер шлёт `jarvis_text` прямо перед звуком этого предложения).
- `abort` в любой момент: сервер прекращает генерацию и шлёт `audio_end` + `state idle`; плата сразу чистит буфер.
- Новый `listen_start` во время ответа = `abort` + новая запись (так делает зажатая BOOT; слово посреди ответа шлёт `abort` и
  `listen_start` по порядку, раздел 9).

## 4. Поток звука

- Сервер отдаёт звук быстрее реального времени не больше чем на 1,5 с вперёд
  (сначала 0,5 с сразу, дальше по часам). Буфер на плате 3 с в PSRAM.
- Если буфер платы пуст во время ответа (сервер не успел синтезировать), плата играет тишину и ждёт.
- Тишина в конце речи, `listen_stop` без звука или речь короче 0,3 с: сервер отвечает `state idle` без ответа.

## 5. Уточнения (после v0.3 платы)

- На `abort` сервер ВСЕГДА отвечает `state idle` (перед ним `audio_end`, если шёл звук), даже если и так был idle.
  Плата выбрасывает пришедший после `abort` звук, пока не увидит это подтверждение.
- `ping` → `pong` сразу, даже во время генерации ответа. 8 с без `pong` плата считает обрывом.
- В ответе на поиск сервер пишет IP того интерфейса, на который пришёл запрос. Если адрес в ответе не совпадает
  с адресом отправителя пакета, плата берёт адрес отправителя (и пишет об этом в лог).
- `audio_start.rate` только 24000, другое плата отвергает с ошибкой.
- Одно `jarvis_text` до ~500 символов (плата держит до 1200 байт на сообщение, кадр до 8 КБ).
- Первые ~200 мс записи по кнопке это звук до `listen_start` (с момента нажатия BOOT). Сервер их не обрезает. У записи по слову
  своя предзапись, см. раздел 7.
- После `audio_end` плата остаётся в SPEAKING, пока доигрывает свой буфер (до 3 с); `state idle` сразу после `audio_end` нормально.
- JSON может содержать `\uXXXX` (как делает `json.dumps` по умолчанию).

## 6. Ошибки

- Нет связи с сервером: сонное лицо NO_SERVER (не ERROR, это ожидание), медленный янтарный светодиод,
  подсказка «Нет связи с ноутбуком», плата снова ищет сервер.
- Сервер не смог (нет интернета/VPN, ИИ не ответил): `state error` с понятным `msg`, например
  «Не могу связаться с ИИ. Проверь VPN на ноутбуке.»

## 7. Слово «Джарвис» (`listen_start` с `"mode":"wake"`, плата v0.4.0)

Слово плата узнаёт сама, на ESP32-S3, без интернета и без сервера: до слова на сервер не уходит ни байта звука.
Версия протокола остаётся 1: сервер, который не знает `mode`, читает запись как обычную (`ptt`), ничего не ломается.
Отличается от кнопки только тем, кто начал и кто закончил запись; остальное (`state`, `user_text`, `jarvis_text`, звук ответа,
`abort`) идёт так же, как в разделах 2–4.

```
плата:  [слово «Джарвис»] → писк → listen_start(wake) → [звук 16 кГц ...] → (пауза 0,8 с) → listen_stop
сервер: state thinking → user_text → jarvis_text → audio_start → [звук 24 кГц] → ... → audio_end → state idle
```

- **С чего начинается звук.** Запись начинается сразу ПОСЛЕ слова: плата само слово не шлёт. Если STT всё же услышит его
  хвост («...вис») или имя целиком, сервер снимает «Джарвис» в начале фразы. Свой писк плата в запись не кладёт:
  запись состоит из предзаписи (до ~150 мс звука между словом и писком, на случай, если человек продолжил без паузы),
  затем пропуска ~310 мс (с v0.4.2; писк стал громче, его эхо в комнате дольше, было ~250 мс), пока плата пищит, и дальше всего
  звука подряд до `listen_stop`. Первые слова, сказанные ровно в этот
  пропуск, теряются, человек должен дождаться писка. Команда `wake beep 0` (то же `wake beep off`) выключает писк и пропуск вместе с ним. Для сервера это
  обычный поток: кадры PCM16, 16 кГц, моно, как при `ptt`.
- **Конец фразы решает плата** по детектору речи (VAD, ESP-SR), а не сервер. Звук после последнего слова до `listen_stop`
  (около 0,8 с тишины) тоже уходит на сервер. Запись заканчивается ровно одним из способов:
  - пауза **800 мс** без речи после того, как речь уже началась;
  - речь так и не началась за **5 с** после слова (ложное срабатывание или человек передумал): в записи почти одна тишина, сервер
    отвечает, как всегда на пустую запись, `state idle` (раздел 4). Плата в этом случае не ждёт ответа, сразу возвращается в покой
    и пишет «Не расслышал», поэтому запоздалый `state idle` ей не мешает;
  - запись длится **12 с**: сервер отвечает на то, что есть (по кнопке остаётся предохранитель 15 с);
  - нажата **BOOT** посреди записи: конец записи как при обычном отпускании, и этим нажатием новая запись по кнопке не
    начинается. Короткое нажатие во время ответа по-прежнему `abort`.
- **Как слово работает во время ответа** (до v0.4.2 оно в это время не слушалось вообще, эхо одним микрофоном не убрать).
  Теперь пока Jarvis думает и говорит, слово может его ПЕРЕБИТЬ (раздел 9, настройка `wake barge`, по умолчанию включена; команда
  `wake barge off` возвращает прежнее поведение). Новая запись по слову после ответа начинается через ~300 мс после того, как
  ответ полностью доиграл и лицо стало спокойным (эхо динамика в комнате). Вообще слово слушается только когда есть Wi-Fi и
  связь с сервером и кнопка не зажата.
- Сервер читает `mode` из `listen_start` (`ptt`, `wake`); нет поля = `ptt` (прошивки до v0.4).
- Все пороги (800 мс, 5 с, 12 с, чувствительность слова, громкость писка 0..5, окно follow, перебивание) и выбор движка слова
  (с v0.5.0 `wake engine mww|esp`: свой microWakeWord или ESP-SR) живут на плате (`wake silence`, `wake thr`, `wake beep`,
  `wake follow`, `wake barge`, `wake engine`); серверу про них знать не нужно, на проводе от движка ничего не меняется.

## 8. Продолжить без слова: `listen_start` с `"mode":"follow"` (плата v0.4.2)

Люди после ответа обычно сразу продолжают говорить («города»: «Москва» — «Архангельск» — «Курск»). Чтобы не говорить «Джарвис»
каждый раз, плата после ответа ещё несколько секунд слушает голос сама.

```
плата:  [ответ доигран] → ~0,3 с эхо → окно (6 с) → [голос, детектор речи (VAD) ≥ 200 мс подряд] → listen_start(follow) →
        [предзапись ~0,5 с + звук 16 кГц ...] → (пауза 0,8 с) → listen_stop
сервер: state thinking → user_text → jarvis_text → audio_start → [звук 24 кГц] → ... → audio_end → state idle
```

- **Когда окно открывается.** Только после ответа, который закончился НОРМАЛЬНО: звук доигран до конца. Не открывается после
  `abort` (короткая BOOT, слово посреди ответа), после ошибки (`state error`), обрыва звука и потери связи, после ответа без звука
  (речь короче 0,3 с). Открывается и после ответа на запись по кнопке, и после ответа на запись `follow`: так цепочка не рвётся.
  Длина окна 6 с (`wake follow <0|2000..15000>`, 0 = выключено), считается от конца эха (~0,3 с после конца ответа).
- **Что начинает запись.** Голос по детектору речи на плате (ESP-SR VADNet) не короче 200 мс подряд, начавшийся уже после открытия
  окна (щелчки и хвост эха короче). Писка нет: лицо показывает «слушаю» (подсказка «Слушаю…»), а когда началась запись, лицо
  обычное LISTENING. Слово «Джарвис» в окне работает как всегда (`mode: "wake"`, писк); но если человек начал фразу со слова,
  голос бывает замечен раньше, чем слово распознано, и тогда запись придёт как `follow`, а «Джарвис» окажется в её начале:
  сервер снимает обращение и в режиме `follow` тоже.
- **Предзапись.** VAD сообщает «речь» с задержкой (~130 мс, пока накопится минимум речи) и плата ждёт ещё 200 мс подтверждения,
  поэтому настоящее начало фразы остаётся примерно на 330 мс позади момента решения. Плата берёт из своего кольца микрофона
  **480 мс** до этого момента (плюс то, на сколько распознавание отстало от микрофона, обычно меньше 100 мс), чтобы не съесть
  первый слог. Значит в начале записи около 0,15-0,3 с без речи (иногда с остатком эха ответа: раньше чем за 150 мс до открытия
  окна плата не берёт). Сервер не должен считать предзапись речью (для `ptt` и `wake` это ~200 мс).
- **Конец записи** по тем же правилам, что у слова: пауза 800 мс без речи или 12 с. «Речь так и не началась за 5 с» здесь не
  бывает: речь к началу записи уже идёт.
- **Если за окно никто не заговорил**, плата тихо возвращается в обычное состояние: ничего серверу не шлёт, «Не расслышал» не
  показывает, не пищит.
- **Что делать серверу.** Режим тот же, что у слова (`ptt`, `wake`, `follow` читаются одним кодом), но запись по голосу без
  слова чаще оказывается чужой болтовнёй, кашлем, телевизором: распознанное пусто, мусорно или явно не обращено к Джарвису. В этом
  случае сервер отвечает так же, как на пустую запись (раздел 4): `state idle` без `user_text`, без звука и без `error`
  (плата в это время в THINKING, `state idle` возвращает её в покой, и окно заново не открывается: ответа не было).
  Сервер, который не знает `follow`, читает запись как `ptt` и отвечает на неё (но без отсева чужих слов).
- **BOOT** работает как всегда: нажатие посреди записи по голосу кончает запись, как отпускание.

## 9. Перебить словом: слово «Джарвис» во время ответа (плата v0.4.2, экспериментально)

Пока Jarvis думает (`thinking`) и говорит (`speaking`), плата продолжает слушать слово. Услышала: замолкает, отменяет ответ и
начинает новую запись, как будто его перебили.

```
плата:  [слово «Джарвис» посреди ответа] → динамик замолк → abort → listen_start(wake) → писк → [звук 16 кГц ...] → listen_stop
сервер: (на abort) [audio_end] → state idle → ... (на listen_stop) state thinking → user_text → jarvis_text → ... → state idle
```

- **Порядок сообщений.** Всегда `abort`, потом `listen_start` (mode `wake`): так сервер сначала отменит ответ и пришлёт
  подтверждение (раздел 5: на `abort` он ВСЕГДА отвечает `state idle`, перед ним `audio_end`, если шёл звук), а потом начнёт
  запись. Наоборот выходило бы «запись, и тут же её прервали». Новый `listen_start` без `abort` (так делает зажатая BOOT) сервер
  по-прежнему понимает как отмену + запись, без подтверждения.
- **Что плата делает со «старым».** Звук ответа, который ещё был в пути, тексты и подтверждение `abort` (`state idle`) плата во
  время записи выбрасывает (лицо LISTENING принадлежит плате, это правило и так действует при записи по кнопке и по слову);
  буфер динамика очищен сразу, поэтому старый звук не доиграется. Подтверждение приходит через миллисекунды после `abort`,
  то есть задолго до конца новой записи (она не короче секунды). Если оно всё же придёт после `listen_stop`, плата примет его за
  «ответа не будет», на миг покажет покой и вернётся в THINKING по `state thinking`.
- **Когда плата НЕ перебивает.** Зажата BOOT; нет связи; ответ уже сам произнёс «Джарвис» (в тексте любого его предложения есть
  «Джарвис» или «Jarvis»: динамик скажет слово сам, микрофон его услышит, плата перебила бы сама себя); слово сказано ещё до
  начала ответа (хвост вопроса); играет диагностика; перебивание выключено командой `wake barge off`. Короткое нажатие BOOT
  работает как раньше: `abort` без новой записи.
- **Себя не слушать.** Пока звучит голос, порог слова на плате строже (у ESP-SR обычный + 0,08, но не выше 0,95; у microWakeWord, который с v0.5.0
  включён по умолчанию, обычный + 0,03, но не выше 0,99; команда `wake barge thr`), а звук, который идёт в распознавание слова (не серверу), ослаблен на 12 дБ: динамик у самого микрофона
  срезает его при обычном усилении. На сервер звук идёт как был. Эхо одним микрофоном не убрать, поэтому перебить словом
  громкий ответ бывает трудно (тогда BOOT), а в редких случаях Jarvis может услышать сам себя.
- Серверу ничего нового знать не нужно: `abort`, `listen_start`, `listen_stop` и ответы на них те же, что в разделах 2-5.
