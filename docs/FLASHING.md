# Прошивка платы и отправка лога

Ничего собирать не нужно: прошивку собирает GitHub, а скрипт сам скачивает её и заливает в плату.

## Один раз: подготовка (Arch Linux)

Аккаунт GitHub не нужен: репозиторий открытый.

1. Поставь программы:

   ```
   sudo pacman -S git curl esptool python-pyserial
   ```

2. Скачай репозиторий:

   ```
   git clone https://github.com/telmiroslav/jarvis.git
   ```

3. Дай себе доступ к USB-портам и **выйди из системы и зайди снова** (или перезагрузись):

   ```
   sudo usermod -aG uucp $USER
   ```

   Проверка после входа: команда `groups` должна показать `uucp`.

## Каждый тест: одна команда

Подключи плату к ноутбуку и выполни:

```
cd jarvis && git pull && ./tools/flash.sh
```

Скрипт скачает последнюю прошивку, зальёт её, перезагрузит плату и покажет её лог.
Подожди около минуты (или сколько скажет Мирослав), сделай проверки из раздела про текущую версию ниже
и нажми **Ctrl+C**.

Один раз (и дальше, только если сменишь Wi-Fi) передай плате домашнюю сеть:

```
./tools/flash.sh wifi
```

Начиная с v0.3 скрипт при прошивке **не трогает настройки платы**: сохранённый Wi-Fi переживает прошивку. Раньше каждая
прошивка стирала их (в файле прошивки на месте настроек лежали пустые байты), и после каждого `./tools/flash.sh`
плата снова писала «Нет Wi-Fi». Если прошиваешь с `--erase`, стирается всё, и Wi-Fi нужно передать заново.

Лог сам сохраняется в папку `~/jarvis-logs`. **Пришли Мирославу самый новый файл оттуда**
(скрипт в конце печатает его имя). Ещё коротко напиши, что видел на плате.

**Самый первый раз** (на плате раньше была другая прошивка) запусти с очисткой памяти:

```
./tools/flash.sh --erase
```

Другие команды:

| Команда | Что делает |
|---|---|
| `./tools/flash.sh` | последняя версия прошивки |
| `./tools/flash.sh v0.0.2` | конкретная версия |
| `./tools/flash.sh --erase` | сначала стереть всю память платы |
| `./tools/flash.sh monitor` | ничего не шить, только смотреть лог (плата перезагрузится) |
| `./tools/flash.sh wifi` | передать плате имя Wi-Fi и пароль (она запомнит их навсегда); не вышло по порту, скрипт сам запишет их прямо в память платы |
| `./tools/flash.sh wifi-nvs` | то же, но сразу «прямой» записью в память платы (если знаешь, что команды по порту не идут) |
| `./tools/flash.sh cmd КОМАНДА` | отправить плате серийную команду и показать ответ: `status`, `wake`, `wake thr 0.55`, `server auto`, `server ws://192.168.1.5:47801/ws`, `echo`, `help` |
| `./tools/flash.sh file путь/к/файлу.bin` | прошить файл с диска |

## Какой USB-порт

У платы два разъёма USB-C: **COM** (UART) и **USB**. Подойдёт любой, а команды (в том числе `./tools/flash.sh wifi`)
плата принимает с обоих.
Если лог не появился (пусто), перетыкни кабель в другой разъём и запусти `./tools/flash.sh monitor`.

## v0.4.0: слово «Джарвис» (без кнопки)

Теперь плата сама слышит слово «Джарвис» (без интернета, прямо на плате): говоришь «Джарвис», она пищит, слушает, и дальше всё
как с кнопкой. Кнопка **BOOT** работает по-прежнему, в любой момент.

Порядок:

1. Обнови сервер на ноутбуке (нужна версия 0.2.0 или новее, иначе «Джарвис» в начале фразы остаётся в тексте):

   ```
   cd jarvis && git pull && ./server/install.sh
   ```

2. Прошей плату:

   ```
   cd jarvis && git pull && ./tools/flash.sh
   ```

   Что будет: скрипт скачает файл около 9 МБ (раньше было 1,5 МБ: в нём теперь лежит модель слова, это нормально), прошивка
   займёт одну-две минуты. Wi-Fi и другие настройки платы не стираются. Потом плата перезагрузится и пойдёт лог.
   Через несколько секунд в логе должна быть строка `WAKE ready: word "Jarvis"`. Если вместо неё `WAKE ... UNAVAILABLE`,
   плата всё равно работает с кнопкой; пришли лог Мирославу.

3. Не закрывай терминал с логом на время проверки (выход из лога: Ctrl+C). Если закрыл, `./tools/flash.sh monitor` покажет
   лог снова (плата при этом перезагрузится, настройки у неё остаются).

Что должно быть:

- [ ] **Подсказка.** Сервер найден, глаза бодрые, внизу жёлтым: **Скажи «Джарвис»**. (Если внизу «Зажми BOOT и говори», слово
  выключено или не поднялось: `./tools/flash.sh cmd wake` скажет почему.)
- [ ] **Слово.** Скажи «Джарвис» обычным голосом, с 1-2 метров. Плата коротко и тихо **пискнет** (два тона), глаза станут шире,
  светодиод красный. Дождись писка и скажи вопрос. Помолчи примерно секунду: плата поймёт, что ты договорил, и дальше обычный ответ.
- [ ] **Тишина.** Скажи «Джарвис» и ничего не говори: через 5 секунд плата сама успокоится, внизу на пару секунд «Не расслышал».
- [ ] **Пока Jarvis думает и говорит, «Джарвис» не слушается.** Так задумано: иначе он включал бы сам себя своим голосом.
  Слух возвращается через долю секунды после конца ответа. Перебить ответ можно, как раньше, кнопкой BOOT.
- [ ] **BOOT.** Зажать, говорить, отпустить работает как в v0.3. Нажатие BOOT посреди записи по слову просто заканчивает запись.
- [ ] **Сама не просыпается.** Поговори с кем-нибудь рядом, включи музыку или телевизор минут на десять: плата не должна пищать.
  Если пищит, смотри «Настройка чувствительности» ниже.

В логе при проверке главные строки: `WAKE detected` (слово услышано, с числами), `WAKE end` (чем кончилась запись),
`WAKE state` (когда слух включается и выключается и почему) и раз в минуту `WAKE stat` (сколько было срабатываний, уровень
микрофона, свободная память).

Настройка чувствительности (команды плате, настройки запоминаются и переживают перезагрузку и прошивку). Пока идёт лог, порт
платы занят: останови лог (Ctrl+C), подай команду, потом снова `./tools/flash.sh monitor`.

| Что случилось | Команда |
|---|---|
| Показать состояние: порог, число срабатываний, уровень микрофона | `./tools/flash.sh cmd wake` |
| Не просыпается на «Джарвис» | `./tools/flash.sh cmd wake thr 0.55` (меньше число = чувствительнее; можно 0.5, но не меньше 0.4) |
| Просыпается сама, от чужих разговоров | `./tools/flash.sh cmd wake thr 0.75` (больше число = строже, не больше 0.9999) |
| Вернуть стандартный порог | `./tools/flash.sh cmd wake thr default` |
| Фраза обрывается на коротких паузах | `./tools/flash.sh cmd wake silence 1200` (пауза в миллисекундах, от 300 до 3000, обычно 800) |
| Ждёт слишком долго после фразы | `./tools/flash.sh cmd wake silence 600` |
| Писк мешает | `./tools/flash.sh cmd wake beep off` (вернуть: `wake beep on`) |
| Выключить слово совсем (останется кнопка) | `./tools/flash.sh cmd wake off`. После перезагрузки плата вообще не запускает движок слова. Вернуть: `./tools/flash.sh cmd wake on`, затем `./tools/flash.sh cmd reboot` |

Если после изменения порога лучше не стало, не крути дальше наугад: пришли Мирославу вывод `./tools/flash.sh cmd wake` и лог.

Что прислать Мирославу:

1. Самый новый файл лога из `~/jarvis-logs` (скрипт в конце печатает его имя). В нём строки `WAKE ...` и `STATUS:`.
2. Вывод команды `./tools/flash.sh cmd wake` после теста.
3. Коротко: просыпалась ли на «Джарвис» с первого раза (сколько раз из скольких), пищала ли сама, и обрывалась ли фраза.

## v0.3: голос (BOOT зажата = говоришь, отпустил = ответ)

Плата теперь разговаривает с сервером на ноутбуке: слушает тебя, пока зажата кнопка **BOOT**, отправляет голос серверу,
показывает ответ субтитрами и проигрывает его динамиком. Нужен запущенный сервер Jarvis на ноутбуке (его ставит
Мирослав; пока его нет, можно проверить плату **поддельным сервером**, см. ниже).

Порядок:

1. Прошей плату: `cd jarvis && git pull && ./tools/flash.sh`
2. Если на плате ещё нет Wi-Fi (на экране «Нет Wi-Fi…»): `./tools/flash.sh wifi`. Скрипт спросит имя сети и пароль,
   покажет, что отправил (пароль заменён звёздочками) и что ответила плата, и напишет, подключилась ли она. Если по
   серийному порту сеть передать не вышло, он **сам** запишет её прямо в память платы (это занимает около минуты:
   читает таблицу разделов, собирает образ, пишет его тем же esptool и перезагружает плату). Ты ничего не меняешь, просто
   дождись «Wi-Fi настроен» и пришли весь вывод Мирославу, если что-то не вышло.
3. Запусти сервер на ноутбуке. Плата найдёт его сама: раз в 3 секунды рассылает по сети запрос и ждёт ответа
   (подробности в `docs/PROTOCOL.md`). Адрес сервера она запоминает.

Что должно быть:

- [ ] **Без сервера.** Пока Wi-Fi нет: сонные глаза и «Нет Wi-Fi…». Wi-Fi есть, а сервера нет: сонные глаза и
  «Ищу ноутбук…», примерно через 12 секунд «Нет связи с ноутбуком. Запущен ли сервер?». Светодиод медленно мигает янтарным.
- [ ] **Сервер нашёлся.** Подсказка исчезает, глаза просыпаются, светодиод зелёный. В логе (`./tools/flash.sh monitor`)
  строки `link: server found ...` и `link: server ready`. Строка `STATUS:` раз в 30 секунд теперь содержит `server=ready`
  и адрес.
- [ ] **Разговор.** Зажми **BOOT** (дольше 0,2 с), говори, отпусти. Пока держишь: глаза шире, вокруг свечение, под
  глазами полоски реагируют на твой голос, светодиод красный.
  Отпустил: глаза смотрят вверх, три точки, светодиод янтарный пульсирует (думает). Потом глаза «дышат» в такт голосу,
  светодиод синий, внизу сначала серая строка «Вы: ...» (что сервер понял), потом ответ по предложениям: каждое
  дописывается к предыдущему, длинный сам плавно уезжает вверх. Звук идёт без щелчков и пауз посреди фразы.
- [ ] **Замолчать.** Пока Jarvis думает или говорит, **коротко** нажми BOOT (меньше 0,2 с): звук сразу обрывается, лицо
  спокойное.
- [ ] **Перебить.** Пока Jarvis говорит, **зажми** BOOT: он сразу замолкает, и начинается новая запись.
- [ ] **Долгая запись.** Если держать BOOT дольше 15 секунд, запись сама заканчивается и сервер отвечает на то, что уже есть.
- [ ] **Ошибка.** Если сервер не смог ответить (нет интернета или VPN на ноутбуке), сонные глаза тёплого янтарного
  цвета, светодиод мигает красным и внизу понятный текст, например «Не могу связаться с ИИ. Проверь VPN на ноутбуке.». Через 8 секунд (или по нажатию BOOT) проходит.
- [ ] **Потеря и возврат связи.** Останови сервер на ноутбуке: за несколько секунд плата напишет «Ищу ноутбук…», потом
  «Нет связи…». Запусти снова: плата вернётся сама, обычно за 3-10 секунд, перезагружать ничего не нужно.
- [ ] **Звонок и самопроверка** при включении (мелодия, `HWCHECK RESULT`, `LOOPBACK`) работают, как в v0.2.

Диагностика звука без сервера: `./tools/flash.sh cmd echo`. Плата запишет 4 секунды с микрофона и проиграет их тебе
(глаза при этом реагируют на настоящий звук). Если это работает, а голос на сервер не доходит, дело в сети, а не в звуке.

Если плата не находит сервер:

1. Ноутбук и плата должны быть в одной сети (не в гостевой Wi-Fi: в ней устройства не видят друг друга).
2. Фаервол ноутбука: нужны порты UDP 47800 и TCP 47801 из домашней сети. Настоящий установщик сервера открывает их сам;
   руками это две команды (если на ноутбуке работает ufw):

   ```
   sudo ufw allow from 192.168.0.0/16 to any port 47800 proto udp
   sudo ufw allow from 192.168.0.0/16 to any port 47801 proto tcp
   ```
3. Задай адрес руками: `./tools/flash.sh cmd server ws://АДРЕС_НОУТБУКА:47801/ws` (адрес смотри командой
   `ip -4 addr` на ноутбуке). Вернуть автоматический поиск: `./tools/flash.sh cmd server auto`.
   Что плата думает про сервер сейчас: `./tools/flash.sh cmd server`.

### Запасной вариант: поддельный сервер (пока настоящий не готов)

Он отвечает заготовленной фразой и тональными гудками, этого достаточно, чтобы увидеть и услышать весь путь
«кнопка, микрофон, сеть, ответ, субтитры, динамик»:

```
pip install websockets        # Arch: sudo pacman -S python-websockets
python3 firmware/test_host/fake_server.py
```

Он слушает те же порты, что настоящий (UDP 47800 и TCP 47801), поэтому нужны те же две команды `ufw` (скрипт печатает их
при запуске). Режимы: `--mode echo` (сервер проигрывает обратно то, что записал с твоего микрофона), `--mode error`
(каждый раз отвечает ошибкой, чтобы посмотреть экран ошибки), `--mode silent` (отвечает «ничего не услышал»),
`--save ПАПКА` (сохраняет записи с микрофона платы в WAV). В выводе видно каждое сообщение платы и уровень принятого
звука в dBFS: если там около -90, микрофон молчит. Остановить: Ctrl+C. Настоящий сервер и поддельный одновременно
не запускай (оба хотят одни и те же порты).

Что прислать Мирославу:

1. Файл лога из `~/jarvis-logs` (самый новый): в нём строки `link:`, `session:`, `STATUS:` и `HWCHECK RESULT`.
2. Коротко, что из списка выше сработало, а что нет. Если что-то не так со звуком (щелчки, обрывы, тихо) или с экраном,
   опиши словами. Если запускал поддельный сервер, перепиши его вывод.
3. Если `./tools/flash.sh wifi` не справился, весь его вывод (он длинный, это нормально).

## Если что-то не так

| Что видишь | Что делать |
|---|---|
| `Нет доступа к порту` | Группа uucp: пункт 3 подготовки, потом выйти и зайти |
| `Не получилось связаться с GitHub` | Проверь интернет и включи VPN, запусти ещё раз |
| `Готовой прошивки на GitHub пока нет` | Релиз ещё собирается: подожди пару минут или сообщение от Мирослава |
| `Релиз v... не найден` | Тег набран неверно. Версии есть на https://github.com/telmiroslav/jarvis/releases |
| `GitHub отказал (код 403 или 429)` | Подожди несколько минут и повтори |
| `Плата не найдена` | Другой кабель (нужен с данными) и другой разъём платы |
| Прошивка не заливается (`Failed to connect`) | Режим загрузки, см. ниже |
| В логе пусто | Нажми RST на плате или перетыкни в другой разъём |
| `Плата не ответила на status` в `./tools/flash.sh wifi` | Скрипт сам напишет вероятные причины (не тот порт, порт занят, старая прошивка) и сам перейдёт к записи сети в память платы. Другой порт: `PORT=/dev/ttyACM1 ./tools/flash.sh wifi` |
| `Плата отказалась сохранить сеть: ... save_failed:...` | Скрипт покажет строки ошибок из лога платы и сам перейдёт к записи сети в память платы. Пришли Мирославу весь вывод |
| `Запасной путь: пишу сеть прямо в память платы` | Так и задумано, ничего не делай, это занимает около минуты. Пароль в этом пути нигде не печатается, временный файл затирается и удаляется |
| `Плата не видит сеть` | Проверь имя (регистр букв важен) и что у роутера включён диапазон 2,4 ГГц |
| `Плата не приняла пароль` | Проверь пароль и запусти `./tools/flash.sh wifi` ещё раз |
| После каждой прошивки «Нет Wi-Fi» | Так было до v0.3 (прошивка стирала настройки). В v0.3 и новее Wi-Fi остаётся; прошей v0.3 и передай сеть ещё раз |
| Внизу «Зажми BOOT и говори», а не «Скажи «Джарвис»» | Слово выключено (`wake off`) или не поднялось. `./tools/flash.sh cmd wake` покажет причину в поле `engine=` (если там не `running`); пришли Мирославу лог |
| «Джарвис» не срабатывает или срабатывает само | Раздел v0.4.0 выше, «Настройка чувствительности» |
| «Ищу ноутбук…» не проходит | Раздел «Если плата не находит сервер» выше (одна сеть, фаервол, адрес руками) |
| Нет звука при ответе, а субтитры есть | `./tools/flash.sh cmd echo`: если эхо слышно, пришли Мирославу лог (там строка `STATUS:` с `underruns` и `overflow`) |
| Вместо часов `--:--` | Плата ещё не подключилась к сети или не достучалась до серверов времени: подожди минуту, потом смотри `TIME synced` в логе |

### Режим загрузки руками

1. Зажми кнопку **BOOT** и держи.
2. Нажми и отпусти кнопку **RST**.
3. Отпусти **BOOT**.
4. Сразу запусти `./tools/flash.sh` ещё раз.

Не помогло: пришли Мирославу текст ошибки из терминала.

## Запасной вариант: прошить из браузера

Нужен Chrome или Chromium. Скрипт не нужен.

1. Скачай `jarvis-firmware.bin`: прямая ссылка на последнюю версию
   https://github.com/telmiroslav/jarvis/releases/latest/download/jarvis-firmware.bin
   (или со страницы https://github.com/telmiroslav/jarvis/releases, раздел Assets). Вход в GitHub не нужен.
2. Открой https://espressif.github.io/esptool-js/ и нажми Connect, выбери порт платы.
3. Flash Address: `0x0`. Выбери скачанный файл. Baudrate можно 460800.
4. Нажми Program. Когда закончится, нажми RST на плате.
5. Лог после этого смотри так: `./tools/flash.sh monitor`.
