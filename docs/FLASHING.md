# Прошивка платы и отправка лога

Ничего собирать не нужно: прошивку собирает GitHub, а скрипт сам скачивает её и заливает в плату.

## Один раз: подготовка (Arch Linux)

Аккаунт GitHub не нужен: репозиторий открытый.

1. Поставь программы:

   ```
   sudo pacman -S git curl esptool python-pyserial
   ```

2. Скачай репозиторий:

   ```
   git clone https://github.com/telmiroslav/jarvis.git
   ```

3. Дай себе доступ к USB-портам и **выйди из системы и зайди снова** (или перезагрузись):

   ```
   sudo usermod -aG uucp $USER
   ```

   Проверка после входа: команда `groups` должна показать `uucp`.

## Каждый тест: одна команда

Подключи плату к ноутбуку и выполни:

```
cd jarvis && git pull && ./tools/flash.sh
```

Скрипт скачает последнюю прошивку, зальёт её, перезагрузит плату и покажет её лог.
Подожди около минуты (или сколько скажет Мирослав), сделай проверки из раздела про текущую версию ниже
и нажми **Ctrl+C**.

Один раз (и дальше, только если сменишь Wi-Fi) передай плате домашнюю сеть:

```
./tools/flash.sh wifi
```

Начиная с v0.3 скрипт при прошивке **не трогает настройки платы**: сохранённый Wi-Fi переживает прошивку. Раньше каждая
прошивка стирала их (в файле прошивки на месте настроек лежали пустые байты), и после каждого `./tools/flash.sh`
плата снова писала «Нет Wi-Fi». Если прошиваешь с `--erase`, стирается всё, и Wi-Fi нужно передать заново.

Лог сам сохраняется в папку `~/jarvis-logs`. **Пришли Мирославу самый новый файл оттуда**
(скрипт в конце печатает его имя). Ещё коротко напиши, что видел на плате.

**Самый первый раз** (на плате раньше была другая прошивка) запусти с очисткой памяти:

```
./tools/flash.sh --erase
```

Другие команды:

| Команда | Что делает |
|---|---|
| `./tools/flash.sh` | последняя версия прошивки |
| `./tools/flash.sh v0.0.2` | конкретная версия |
| `./tools/flash.sh --erase` | сначала стереть всю память платы |
| `./tools/flash.sh monitor` | ничего не шить, только смотреть лог (плата перезагрузится) |
| `./tools/flash.sh wifi` | передать плате имя Wi-Fi и пароль (она запомнит их навсегда); не вышло по порту, скрипт сам запишет их прямо в память платы |
| `./tools/flash.sh wifi-nvs` | то же, но сразу «прямой» записью в память платы (если знаешь, что команды по порту не идут) |
| `./tools/flash.sh cmd КОМАНДА` | отправить плате серийную команду и показать ответ: `status`, `wake`, `wake thr 0.88`, `server auto`, `server ws://192.168.1.5:47801/ws`, `echo`, `aec`, `music stat`, `help` |
| `./tools/flash.sh file путь/к/файлу.bin` | прошить файл с диска |

## Какой USB-порт

У платы два разъёма USB-C: **COM** (UART) и **USB**. Подойдёт любой, а команды (в том числе `./tools/flash.sh wifi`)
плата принимает с обоих.
Если лог не появился (пусто), перетыкни кабель в другой разъём и запусти `./tools/flash.sh monitor`.

## v0.6.1: слово больше не выключается само после обычного сброса платы

Плата, запуская движок слова, ставит себе пометку «идёт запуск» и снимает её только через 30 секунд нормальной работы. Если пометка осталась после
перезагрузки, плата считала, что движок упал, и выключала слово (ESP-SR) или насовсем меняла свою модель на ESP-SR (microWakeWord). Причину
перезагрузки она не смотрела, поэтому тем же считались вытащенный кабель, `reboot`, `./tools/flash.sh monitor` (он перезагружает плату), перепрошивка
и ноутбук, на секунду отключивший USB-порты. Две такие перезагрузки подряд в первые 30 секунд, и слово пропадало (в логе
`WAKE on state=unavailable(previous_start_crashed)`, а твоя модель заменялась на ESP-SR: `word_engine=esp(selected=esp)`). Что изменено:

- Плата смотрит, чем кончился прошлый запуск. Движок виноват, только если это настоящее падение программы: `PANIC`, `INT_WDT`, `TASK_WDT`, `WDT`
  или `CPU_LOCKUP`. Питание, кнопка RST, `reboot`, USB, перепрошивка, просадка питания (`BROWNOUT`) и неизвестная причина падением не считаются:
  плата запускает ту же модель, что выбрана, и ничего не выключает.
- После настоящего падения всё как раньше: с microWakeWord плата переходит на ESP-SR и запоминает это (вернуть: `wake engine mww` и `reboot`), с ESP-SR в этом
  запуске слова нет. Но теперь это только на один запуск: следующая загрузка (любая) пробует движок снова, команда `wake on` для этого не нужна.
- В логе у каждого из этих случаев одна строка с причиной перезагрузки. Не падение: `start guard was left by a reset that is not a crash (USB): starting the
  engine as usual`. Просадка питания: `start guard was left by a power reset (BROWNOUT!!!) ...` (проверь кабель и блок питания). Падение: `the board crashed (PANIC!!!) ...`.

Прошивка (сервер обновлять не нужно, протокол тот же):

```
cd jarvis && git pull && ./tools/flash.sh
```

Wi-Fi и другие настройки платы не стираются.

Что проверить:

- [ ] Дважды подряд перетыкни кабель или запусти `./tools/flash.sh monitor` в первые 30 секунд после включения. В логе строки `start guard was left by a reset that is not a crash (USB)`
  (или `EXT`, `POWERON`, `SW`), а потом `WAKE engine: mww`; слово работает. Строк `previous_start_crashed` и `switching to the ESP-SR engine` быть не должно.
- [ ] `./tools/flash.sh cmd wake` в тишине показывает `WAKE on state=armed` и `engine=running`, а ниже `WAKE v0.5.0 word_engine=mww(selected=mww)`.

Если слово уже пропало на старой прошивке (`unavailable(previous_start_crashed)` или `word_engine=esp(selected=esp)` без причины в виде настоящего падения
в логе), верни его так (после прошивки v0.6.1 это нужно один раз, если плата уже успела сохранить ESP-SR):

```
./tools/flash.sh cmd wake on
./tools/flash.sh cmd wake engine mww
./tools/flash.sh cmd reboot
```

## v0.6.0: музыка на колонке и слово «Джарвис» поверх неё

Что нового:

- **Музыка играет из динамика платы.** «Джарвис, включи …» (нужен сервер 0.5.0 или новее, он сам находит трек и присылает звук). На лице спокойные глаза
  и строка «♪ название»; на паузе «⏸ название». Громкость музыки задаёт сервер (по умолчанию 40 из 100), голос Джарвиса её не меняет.
- **Слово поверх музыки.** Плата слушает «Джарвис» и пока играет музыка: она вычитает из микрофона то, что сама играет (эхоподавление ESP-SR AEC, опорный
  сигнал берётся прямо с динамика), порог слова строже, как при перебивании. Сказал слово посреди музыки: музыка сразу на паузе, писк, говори; потом музыку
  продолжает (или нет) сервер. Эхоподавление работает только пока динамик играет и только для слова: на сервер звук идёт как был. То же эхоподавление
  работает и когда говорит сам Джарвис (перебить словом стало легче), выключить это: `aec voice off`.
- **BOOT коротко = стоп музыки** (когда ничего не записывается и Джарвис молчит), и на паузе тоже.
- Окно «Слушаю…» после ответа при музыке не открывается.

**Главное предупреждение.** Эту версию писали без платы в руках: ESP-SR AEC, выравнивание по времени и память проверены только на компьютере (логика) и по
документации Espressif. Что получится на железе, покажет твой лог. Поэтому всё настраивается командами и всё меряется.

Прошивка (сервер обновить до 0.5.0 или новее; без него музыка не включится, остальное как раньше):

```
cd jarvis && git pull && ./tools/flash.sh
```

Что должно быть в логе при старте:

- `# JARVIS v0.6.0 ...`, строка `music buffer: 96000 samples (4.0 s ...)`.
- `AEC ready: ESP-SR ... frame 512 samples (32 ms) ...`. Если вместо неё `AEC not started: ...` или `WAKE v0.6.0: echo cancellation is NOT running (...)`, пришли
  лог Мирославу: слово поверх музыки тогда работает только строже порогом (музыку лучше потише).
- В строке `STATUS:` теперь `music=off aec=idle`.

Проверка без сервера (музыку играет сама плата, ноутбук нужен только включённый сервер для связи):

```
./tools/flash.sh cmd music test
```

Звучит синтетическая «музыка» (бас, аккорды, ритм). Скажи «Джарвис» поверх неё с 1 метра: музыка встаёт на паузу (не мгновенно: около 0,1 с, пока доиграет
очередь динамика), писк, плата слушает. Сервер про тестовую музыку не знает и продолжения не пришлёт, поэтому после ответа:

```
./tools/flash.sh cmd music resume      # продолжить тест (music stop или BOOT коротко: стоп)
```

Что проверить (отметь, сколько раз из десяти получилось):

- [ ] **Музыка с сервера.** «Джарвис, включи …»: музыка идёт из платы, строка «♪ название», слышно без треска и пропусков (в логе раз в 10 с
  `MUSIC stat: ... underruns 0`; `silent chunks` растут только в начале запуска).
- [ ] **Слово поверх музыки.** При громкости музыки 40, потом 60 и 80 (скажи «Джарвис, громче»): сколько раз из десяти плата услышала слово с 1 метра.
  В логе строка `WAKE detected ... p=...`, при провале `WAKE near-miss`. Это главный результат этой версии.
- [ ] **Пауза и продолжение.** После ответа музыка продолжается без провала (серверное `music_resume`); название на лице то же.
- [ ] **BOOT коротко посреди музыки = стоп**, и в паузе тоже. Строка `MUSIC: BOOT short press = stop`.
- [ ] **Окно «Слушаю…»** при музыке не появляется.
- [ ] **Перебить словом ответ Джарвиса** (v0.4.2): теперь с эхоподавлением. Если стало хуже, чем в v0.5.1: `aec voice off` и напиши.
- [ ] Строка `HEAP ok` каждые 30 секунд остаётся `ok` (в том числе при музыке и после неё).

Как настроить эхоподавление (всё запоминается, команды подавай, когда лог остановлен: Ctrl+C):

```
./tools/flash.sh cmd aec                # состояние, время на кадр, ослабление эха (ERLE), выравнивание
./tools/flash.sh cmd music stat         # буфер, недоборы, громкость + одна строка про эхоподавление
```

- **Задержка.** Динамик слышен микрофону с задержкой около 60 мс (очередь динамика 6 буферов по 10 мс и сам микрофон); если задержку на плате выставить неверно, эхо
  почти не вычитается. Плата умеет измерить её сама: в тишине, на громкости как при музыке, `aec cal`; плата 1,8 с играет шум и слушает его, подожди 5 секунд и
  `aec`: в строках `AEC cal ...` будет, сколько миллисекунд, и `aec delay` поставится сам (на 6 мс меньше измеренного: опора должна идти чуть впереди эха).
  Вручную: `aec delay 60` (0..250).
- **Что показывает `aec` при музыке.** `erle_db=` насколько эхо ослаблено (энергия до и после на кадрах со звучащей опорой): хорошо 15..30, ниже 6 значит, что опора
  не совпала по времени (сделай `aec cal`) или динамик искажает; `cpu=` доля ядра 1, `skipped=` кадры, которые AEC не успел (должно быть 0), `aligned=yes`.
- **Стенд `aec bench`.** В тишине, пока динамик молчит: `./tools/flash.sh cmd aec bench`, через 8 секунд `./tools/flash.sh cmd aec`. Строки `AEC bench ...`:
  время на кадр (какую долю ядра съедает AEC), ослабление синтетического эха и сколько речи поверх эха сохраняется. Пришли их Мирославу.
- **Режим.** `aec mode fd_low` (по умолчанию), `sr_low` (только линейный фильтр, быстрее и мягче к речи), `sr_high`, `fd_high`. `aec nlp 0|1|2` (только fd): подавитель остатка,
  0 мягкий. `aec taps 4` (1..8): длина фильтра, больше = дольше хвост эха и больше процессора. После смены режима плата пересоздаёт AEC, когда динамик молчит.
- **Выключить и сравнить.** `aec off` (запоминается; чтобы включить обратно: `aec on` и `reboot`). Слово поверх музыки тогда держится только на строгом пороге.
- **Если эхоподавление упало** (плата перезагрузилась, пока оно считало): при следующей загрузке в логе будет `the board restarted while the AEC was working ...`, а само
  эхоподавление выключено и сохранено выключенным, чтобы плата не падала при каждой музыке. Пришли лог падения (он выше этой строки); вернуть: `aec on` и `reboot`.
- **Порог слова при музыке** общий с перебиванием: `wake barge thr 0.95` строже, `wake barge thr default` как есть. Громкость музыки для проверки: `music vol 30`.

Пришли Мирославу: весь лог, вывод `aec` и `music stat`, снятый ПОСРЕДИ музыки (не после), вывод `aec bench` и `aec cal`, и сколько раз из десяти слышит слово при громкости 40, 60 и 80.

## v0.5.1: запись по слову больше не обрывается (связь)

В логе v0.5.0 два раза посреди записи по слову пропадала связь с ноутбуком («connection to the server lost»), и фраза терялась.
Вероятная причина: сеть на плате иногда секунду не принимала звук, а библиотека в этом случае сразу рвёт соединение. Что изменено:

- Wi-Fi на плате больше не «спит» между маяками роутера (плата питается от USB): подтверждения от ноутбука приходят без задержки.
- Плата перед отправкой звука проверяет, что сеть готова его принять. Не готова: звук ждёт в памяти (до 2 секунд), связь не рвётся.
  Каждое такое ожидание пишется в лог строкой `TX stall ended: the socket accepted no data for N ms`.
- Пока слово записывает фразу (и при нажатой BOOT), движок слова ничего не считает: процессор остаётся Wi-Fi и звуку.
  После записи он начинает с чистого состояния и первую секунду «глух», это нормально.
- Любая ошибка связи пишет в лог одну строку с силой сигнала, памятью, очередью звука и загрузкой процессора.

Прошивка (сервер обновлять не нужно, протокол тот же):

```
cd jarvis && git pull && ./tools/flash.sh
```

Что должно быть:

- [ ] В логе при подключении к Wi-Fi строка `Wi-Fi power save: MIN_MODEM -> NONE`.
- [ ] Скажи «Джарвис» десять раз и каждый раз продиктуй фразу секунд на пять: запись должна доходить до ответа. Строк
  `connection to the server lost` в логе быть не должно. Если они есть, пришли лог Мирославу: рядом в той же строке написана причина.
- [ ] Строки `TX stall ended` допустимы, если они редкие и короткие (до секунды). Если их много, тоже пришли лог.

Отдельная просьба Мирослава: измерить, на что движок слова тратит время (в доме тихо, плата в покое, на экране «Скажи «Джарвис»»).

```

```


## v0.5.0: слово «Джарвис» теперь узнаёт твоя собственная модель (microWakeWord)

Что нового:

- **Слово узнаёт модель, которую ты сам обучил** (`jarvis_ru`, microWakeWord). Она включена по умолчанию. Старый движок
  (ESP-SR, как в v0.4.2) остался: его можно включить командой и вернуть назад (ниже).
- Конец фразы по-прежнему определяет детектор речи ESP-SR. Он теперь работает один, без распознавания слова, это экономит
  процессор и память платы.
- Всё остальное из v0.4.2 работает как раньше: окно «Слушаю…» после ответа, перебивание словом, громкий писк, строка `HEAP ...`.
- Порог срабатывания нового движка по умолчанию 0.90. У каждого движка свой порог, они не мешают друг другу.
- Модель обучалась на микрофоне ноутбука, а у платы свой микрофон, поэтому на плате она может пропускать слово или чуть
  чаще срабатывать зря. Для этого в логе теперь есть строки `WAKE near-miss` («почти слово»): плата почти услышала «Джарвис»,
  но не хватило совсем немного. По ним Мирослав увидит, нужно ли менять порог.

Прошивка (сервер обновлять не нужно, протокол тот же):

```
cd jarvis && git pull && ./tools/flash.sh
```

Wi-Fi и другие настройки платы не стираются. Через несколько секунд после включения в логе должны быть строки
`microWakeWord ready` и `WAKE engine: mww`. Первую секунду после включения слово не слушается (движок прогревается), это нормально.
Не закрывай терминал на время проверки (выход из лога: Ctrl+C).

Что должно быть:

- [ ] **Движок.** В логе `WAKE engine: mww`. Если там `WAKE engine: esp AFTER A FALLBACK`, значит новый движок не поднялся и
  плата работает на старом: всё работает, но пришли лог Мирославу (в строке написана причина).
- [ ] **Слово.** Скажи «Джарвис» десять раз обычным голосом с 1 метра: плата пищит и слушает. Запомни, сколько раз из десяти.
  Потом то же с 2-3 метров. В логе каждое срабатывание это строка `WAKE detected ... engine=mww p=0.94 peak=0.98`: `p` это насколько
  плата уверена (должно быть выше порога 0.90).
- [ ] **«Почти слово».** Если слово не сработало, в логе будет строка `WAKE near-miss: ... peaked at 0.87, below the cutoff 0.900`.
  Число около 0.85-0.89 значит, что плата почти услышала.
- [ ] **Сама не просыпается.** Поговори с кем-нибудь рядом или включи музыку или телевизор минут на десять: плата не должна пищать.
- [ ] **Окно «Слушаю…» и перебивание словом** (как в v0.4.2): игра в «города» без слова «Джарвис» и «Джарвис» посреди ответа.

Что должно быть:

- [ ] **Без сервера.** Пока Wi-Fi нет: сонные глаза и «Нет Wi-Fi…». Wi-Fi есть, а сервера нет: сонные глаза и
  «Ищу ноутбук…», примерно через 12 секунд «Нет связи с ноутбуком. Запущен ли сервер?». Светодиод медленно мигает янтарным.
- [ ] **Сервер нашёлся.** Подсказка исчезает, глаза просыпаются, светодиод зелёный. В логе (`./tools/flash.sh monitor`)
  строки `link: server found ...` и `link: server ready`. Строка `STATUS:` раз в 30 секунд теперь содержит `server=ready`
  и адрес.
- [ ] **Разговор.** Зажми **BOOT** (дольше 0,2 с), говори, отпусти. Пока держишь: глаза шире, вокруг свечение, под
  глазами полоски реагируют на твой голос, светодиод красный.
  Отпустил: глаза смотрят вверх, три точки, светодиод янтарный пульсирует (думает). Потом глаза «дышат» в такт голосу,
  светодиод синий, внизу сначала серая строка «Вы: ...» (что сервер понял), потом ответ по предложениям: каждое
  дописывается к предыдущему, длинный сам плавно уезжает вверх. Звук идёт без щелчков и пауз посреди фразы.
- [ ] **Замолчать.** Пока Jarvis думает или говорит, **коротко** нажми BOOT (меньше 0,2 с): звук сразу обрывается, лицо
  спокойное.
- [ ] **Перебить.** Пока Jarvis говорит, **зажми** BOOT: он сразу замолкает, и начинается новая запись.
- [ ] **Долгая запись.** Если держать BOOT дольше 15 секунд, запись сама заканчивается и сервер отвечает на то, что уже есть.
- [ ] **Ошибка.** Если сервер не смог ответить (нет интернета или VPN на ноутбуке), сонные глаза тёплого янтарного
  цвета, светодиод мигает красным и внизу понятный текст, например «Не могу связаться с ИИ. Проверь VPN на ноутбуке.». Через 8 секунд (или по нажатию BOOT) проходит.
- [ ] **Потеря и возврат связи.** Останови сервер на ноутбуке: за несколько секунд плата напишет «Ищу ноутбук…», потом
  «Нет связи…». Запусти снова: плата вернётся сама, обычно за 3-10 секунд, перезагружать ничего не нужно.
- [ ] **Звонок и самопроверка** при включении (мелодия, `HWCHECK RESULT`, `LOOPBACK`) работают, как в v0.2.

Диагностика звука без сервера: `./tools/flash.sh cmd echo`. Плата запишет 4 секунды с микрофона и проиграет их тебе
(глаза при этом реагируют на настоящий звук). Если это работает, а голос на сервер не доходит, дело в сети, а не в звуке.

Если плата не находит сервер:

1. Ноутбук и плата должны быть в одной сети (не в гостевой Wi-Fi: в ней устройства не видят друг друга).
2. Фаервол ноутбука: нужны порты UDP 47800 и TCP 47801 из домашней сети. Настоящий установщик сервера открывает их сам;
   руками это две команды (если на ноутбуке работает ufw):

   ```
   sudo ufw allow from 192.168.0.0/16 to any port 47800 proto udp
   sudo ufw allow from 192.168.0.0/16 to any port 47801 proto tcp
   ```
3. Задай адрес руками: `./tools/flash.sh cmd server ws://АДРЕС_НОУТБУКА:47801/ws` (адрес смотри командой
   `ip -4 addr` на ноутбуке). Вернуть автоматический поиск: `./tools/flash.sh cmd server auto`.
   Что плата думает про сервер сейчас: `./tools/flash.sh cmd server`.

### Запасной вариант: поддельный сервер (пока настоящий не готов)

Он отвечает заготовленной фразой и тональными гудками, этого достаточно, чтобы увидеть и услышать весь путь
«кнопка, микрофон, сеть, ответ, субтитры, динамик»:

```
pip install websockets        # Arch: sudo pacman -S python-websockets
python3 firmware/test_host/fake_server.py
```

Он слушает те же порты, что настоящий (UDP 47800 и TCP 47801), поэтому нужны те же две команды `ufw` (скрипт печатает их
при запуске). Режимы: `--mode echo` (сервер проигрывает обратно то, что записал с твоего микрофона), `--mode error`
(каждый раз отвечает ошибкой, чтобы посмотреть экран ошибки), `--mode silent` (отвечает «ничего не услышал»),
`--save ПАПКА` (сохраняет записи с микрофона платы в WAV). В выводе видно каждое сообщение платы и уровень принятого
звука в dBFS: если там около -90, микрофон молчит. Остановить: Ctrl+C. Настоящий сервер и поддельный одновременно
не запускай (оба хотят одни и те же порты).

Что прислать Мирославу:

1. Файл лога из `~/jarvis-logs` (самый новый): в нём строки `link:`, `session:`, `STATUS:` и `HWCHECK RESULT`.
2. Коротко, что из списка выше сработало, а что нет. Если что-то не так со звуком (щелчки, обрывы, тихо) или с экраном,
   опиши словами. Если запускал поддельный сервер, перепиши его вывод.
3. Если `./tools/flash.sh wifi` не справился, весь его вывод (он длинный, это нормально).

## Если что-то не так

| Что видишь | Что делать |
|---|---|
| `Нет доступа к порту` | Группа uucp: пункт 3 подготовки, потом выйти и зайти |
| `Не получилось связаться с GitHub` | Проверь интернет и включи VPN, запусти ещё раз |
| `Готовой прошивки на GitHub пока нет` | Релиз ещё собирается: подожди пару минут или сообщение от Мирослава |
| `Релиз v... не найден` | Тег набран неверно. Версии есть на https://github.com/telmiroslav/jarvis/releases |
| `GitHub отказал (код 403 или 429)` | Подожди несколько минут и повтори |
| `Плата не найдена` | Другой кабель (нужен с данными) и другой разъём платы |
| Прошивка не заливается (`Failed to connect`) | Режим загрузки, см. ниже |
| В логе пусто | Нажми RST на плате или перетыкни в другой разъём |
| `Плата не ответила на status` в `./tools/flash.sh wifi` | Скрипт сам напишет вероятные причины (не тот порт, порт занят, старая прошивка) и сам перейдёт к записи сети в память платы. Другой порт: `PORT=/dev/ttyACM1 ./tools/flash.sh wifi` |
| `Плата отказалась сохранить сеть: ... save_failed:...` | Скрипт покажет строки ошибок из лога платы и сам перейдёт к записи сети в память платы. Пришли Мирославу весь вывод |
| `Запасной путь: пишу сеть прямо в память платы` | Так и задумано, ничего не делай, это занимает около минуты. Пароль в этом пути нигде не печатается, временный файл затирается и удаляется |
| `Плата не видит сеть` | Проверь имя (регистр букв важен) и что у роутера включён диапазон 2,4 ГГц |
| `Плата не приняла пароль` | Проверь пароль и запусти `./tools/flash.sh wifi` ещё раз |
| После каждой прошивки «Нет Wi-Fi» | Так было до v0.3 (прошивка стирала настройки). В v0.3 и новее Wi-Fi остаётся; прошей v0.3 и передай сеть ещё раз |
| Внизу «Зажми BOOT и говори», а не «Скажи «Джарвис»» | Слово выключено (`wake off`) или не поднялось. `./tools/flash.sh cmd wake` покажет причину в поле `engine=` (если там не `running`); пришли Мирославу лог |
| «Джарвис» не срабатывает или срабатывает само | Раздел v0.4.0 выше, «Настройка чувствительности» |
| «Ищу ноутбук…» не проходит | Раздел «Если плата не находит сервер» выше (одна сеть, фаервол, адрес руками) |
| Нет звука при ответе, а субтитры есть | `./tools/flash.sh cmd echo`: если эхо слышно, пришли Мирославу лог (там строка `STATUS:` с `underruns` и `overflow`) |
| Вместо часов `--:--` | Плата ещё не подключилась к сети или не достучалась до серверов времени: подожди минуту, потом смотри `TIME synced` в логе |

### Режим загрузки руками

1. Зажми кнопку **BOOT** и держи.
2. Нажми и отпусти кнопку **RST**.
3. Отпусти **BOOT**.
4. Сразу запусти `./tools/flash.sh` ещё раз.

## Запасной вариант: прошить из браузера

Нужен Chrome или Chromium. Скрипт не нужен.

1. Скачай `jarvis-firmware.bin`: прямая ссылка на последнюю версию
   https://github.com/telmiroslav/jarvis/releases/latest/download/jarvis-firmware.bin
   (или со страницы https://github.com/telmiroslav/jarvis/releases, раздел Assets). Вход в GitHub не нужен.
2. Открой https://espressif.github.io/esptool-js/ и нажми Connect, выбери порт платы.
3. Flash Address: `0x0`. Выбери скачанный файл. Baudrate можно 460800.
4. Нажми Program. Когда закончится, нажми RST на плате.
5. Лог после этого смотри так: `./tools/flash.sh monitor`.
